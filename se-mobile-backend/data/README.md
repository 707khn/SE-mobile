# Выгрузки для сидеров

Здесь лежит только список сотрудников — ФИО, должность, подразделение,
табельный номер. То же, что висит на стене; на нём держится добрая половина
проверок.

**Зарплаты и проходов через турникет здесь нет, и так задумано.** Раньше они
лежали рядом: расчётные листки 124 человек по статьям и время каждого прохода
за двадцать дней. В репозитории это расходилось с каждой копией, попадало в
каждую сборку и оставалось в истории git навсегда — притом что сидеры своё
давно отработали, а данные живут в базе и в зашифрованных суточных копиях
(`/var/backups/se-mobile`).

Поднимать сервер с нуля правильнее из копии, а не повторной загрузкой.

## Если выгрузку надо загрузить

Положите файл **на сервер**, а не сюда:

```bash
sudo mkdir -p /var/lib/se-mobile/seed-data
sudo chown root:semobile /var/lib/se-mobile/seed-data
sudo chmod 750 /var/lib/se-mobile/seed-data
sudo cp payslips_2026_08.json /var/lib/se-mobile/seed-data/
sudo systemctl restart se-mobile
```

Путь меняется переменной `SEED_DATA_DIR`. Ищется по файлам, а не по папке
целиком: положив туда одни листки, вы не отменяете список сотрудников,
который лежит здесь.

| Файл | Что в нём | Где лежит |
|---|---|---|
| `employees_2026_07.csv` | табельный номер, временный id, ФИО, должность, подразделение | здесь |
| `access_ГОД_МЕСЯЦ.csv` | проходы турникета за месяц | только на сервере |
| `payslips_ГОД_МЕСЯЦ.json` | книга расчётных листков за месяц | только на сервере |

Новый месяц листков подхватится сам, но сидеру нужно поднять версию в
`_SEED_VERSIONS` — иначе журнал `applied_seeds` посчитает, что своё он уже
отработал.

## Проверки

Три проверки в `tests/test_directory_staff.py` работают именно на этих
выгрузках — в том числе та, что нашла две ошибки разбора: долг на конец июня
должен сойтись с долгом на начало июля. Без файлов они **пропускаются с
причиной**, а не молчат:

```
SKIPPED payslips_2026_06.json нет: выгрузка не лежит в SEED_DATA_DIR
```

Положите выгрузки в `SEED_DATA_DIR` — и они снова пойдут:

```bash
SEED_DATA_DIR=~/выгрузки pytest tests/
```

## Про историю git

Удаление из рабочего дерева не убирает файлы из прошлых коммитов: их всё ещё
достанет любой, у кого есть доступ к репозиторию. Убрать оттуда можно только
переписав историю (`git filter-repo`) с принудительной отправкой в `main` —
это ломает все существующие копии, и решать это вам.
