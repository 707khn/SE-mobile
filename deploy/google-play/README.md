# Публикация в Google Play

Что сделано в коде, что нужно сделать в Play Console и что отвечать в его
анкетах. Порядок — тот, в котором Play Console сам это спрашивает.

## Что уже готово в коде

| Что | Где |
|---|---|
| Сборка для Play: `.aab`, имя пакета `com.sebtrz.mobile` | `--dart-define=STORE=play`, `android/app/build.gradle` |
| Своя проверка обновлений в сборке для Play выключена — правила Play её запрещают | `lib/utils/store.dart`, `lib/utils/app_update.dart` |
| Нет разрешений, которые Play отклоняет: доступ ко всем файлам, список приложений, установка пакетов | `android/app/src/main/AndroidManifest.xml` |
| Целевая версия Android — 36, её задаёт Flutter 3.47; Play требует не ниже прошлогодней | `flutter.targetSdkVersion` |
| CI после каждого слияния в `main` собирает `.aab` и проверяет, что Play его пропустит | `.github/workflows/build-apk.yml`, файл `se-mobile-play-…aab` в Releases |
| Та же сборка — в каждом PR, который трогает Android | `.github/workflows/android-check.yml` |
| Политика конфиденциальности | `https://api.se-btrz.com/privacy` |
| Учётная запись для проверяющих | `se-mobile-backend/review_account.py` |
| Значок и обложка для карточки | `icon-512.png`, `feature-graphic-1024x500.png` здесь же |

**Имя пакета `com.sebtrz.mobile` после первой публикации сменить нельзя.**
Сборка для раздачи с нашего сервера остаётся под старым именем, чтобы у тех,
кто уже поставил приложение, обновления приходили как раньше. Для телефона это
два разных приложения: кто перейдёт на Play, старое удаляет.

## 1. Аккаунт разработчика

play.google.com/console → создать аккаунт, **$25 один раз**.

- **Организация** (рекомендую): разработчиком в магазине будет значиться
  АО «Семей инжиниринг». Нужен номер **D-U-N-S** — бесплатный, выдаётся от
  нескольких дней до пары недель (dnb.com). Понадобится и для Apple.
- Личный аккаунт быстрее, но перед первой публикацией Google требует
  закрытое тестирование: не меньше 12 человек в течение 14 дней.

## 2. Создать приложение

«Создать приложение»: название **SE Mobile**, язык по умолчанию — русский,
**Приложение**, **Бесплатное**.

## 3. Сервер: политика и учётная запись для проверки

Адрес для вопросов о данных — в `/etc/se-mobile.env`, иначе на странице
будет «ОИТиС» без адреса:

```bash
echo 'PRIVACY_CONTACT=ваш-адрес@se-btrz.com' | sudo tee -a /etc/se-mobile.env
sudo systemctl restart se-mobile
curl -s --resolve api.se-btrz.com:443:127.0.0.1 https://api.se-btrz.com/privacy | grep -c 'Политика'
```

**Текст политики составлен по устройству приложения, а не юристом.** Перед
публикацией его должен прочитать тот, кто на предприятии отвечает за
персональные данные; правится он в `se-mobile-backend/privacy.py`.

Учётная запись для проверяющих — вымышленный сотрудник со своими листками и
проходами, настоящих данных проверяющий не увидит:

```bash
sudo bash -c 'set -a; . /etc/se-mobile.env; set +a; \
    /opt/se-mobile/venv/bin/python /opt/se-mobile/se-mobile-backend/review_account.py'
```

Печатает логин (`review`) и пароль. Повторный запуск — новый пароль; убрать
совсем — тот же запуск с `--remove`.

## 4. «Содержание приложения» (App content)

| Раздел | Ответ |
|---|---|
| Политика конфиденциальности | `https://api.se-btrz.com/privacy` |
| Доступ к приложению | «Всё или часть функций ограничены» → добавить инструкцию: логин `review`, пароль из шага 3, «Вход по логину и паролю на первом экране» |
| Реклама | Нет |
| Возрастные ограничения (анкета IARC) | Категория «Утилиты, продуктивность…»; на все вопросы о насилии, азартных играх, общении пользователей и т. п. — «Нет». Выйдет 3+ / «Для всех» |
| Целевая аудитория | 18 лет и старше. Приложение не для детей |
| Новостное приложение | Нет (новости — внутренние, предприятия) |
| Финансовые функции | «Приложение не предоставляет финансовых функций» — расчётный листок только показывается, денег приложение не переводит |
| Приложение для здоровья | Нет |
| Государственное приложение | Нет |
| Удаление аккаунта | Учётные записи заводит предприятие, зарегистрироваться в приложении нельзя; если анкета всё же спросит адрес — `https://api.se-btrz.com/privacy` (раздел «Ваши права») |

### Безопасность данных (Data safety)

Отвечать по тому, что **уходит с телефона** — так Google определяет «сбор».
Данные, которые приложение получает с сервера и показывает (листки, проходы),
сбором не считаются.

- Собирает ли приложение данные: **Да**.
- Шифруются ли при передаче: **Да** (только HTTPS).
- Можно ли запросить удаление: **Да** (через контакт из политики).

| Тип данных | Собирается | Передаётся третьим лицам | Обязательно | Зачем |
|---|---|---|---|---|
| Личная информация → **Идентификаторы пользователя** (табельный номер) | Да | Нет | Да | Функциональность приложения, управление аккаунтом |
| Идентификаторы устройства → **Device or other IDs** (токен уведомлений Firebase) | Да | Нет* | Нет | Функциональность приложения (уведомления) |

\* Токен уходит в Firebase Cloud Messaging, но это служба, которая работает
от нашего имени (service provider), — Google это передачей третьим лицам не
считает.

Пароль в анкете не указывают: он не хранится, а только проверяется. Версия
приложения — служебная информация, не персональные данные.

## 5. Карточка в магазине (Main store listing)

**Короткое описание** (до 80 знаков):

> Расчётный листок, проходы, отпуск, меню и новости для работников предприятия

**Полное описание:**

> SE Mobile — приложение для работников АО «Семей инжиниринг».
>
> • Расчётный листок: начисления, удержания и сумма к выплате за каждый месяц.
> • Проходы: когда вы пришли и ушли через проходную, за день или период.
> • Отпуск: сколько дней осталось.
> • Меню столовой по дням.
> • Новости предприятия и служебный справочник с телефонами.
> • Казахский и русский языки, тёмная тема, вход по коду.
>
> Войти может только работник предприятия: логин и пароль выдаёт отдел
> информационных технологий и связи (ОИТиС).

**Графика:**

- значок 512×512 — `icon-512.png`;
- обложка 1024×500 — `feature-graphic-1024x500.png`;
- **снимки экрана телефона — минимум 2, лучше 4–6.** Снимайте под учётной
  записью `review`, а не своей: на снимках не должно быть настоящей зарплаты
  и чужих ФИО. Подойдут: главный экран, расчётный листок, проходы, меню.

**Категория:** «Бизнес». Контакты: адрес почты предприятия (обязателен),
сайт `https://se-btrz.com`.

## 6. Первый выпуск

1. Скачать `.aab`: GitHub → **Releases** → верхний релиз (`v<версия>-<номер>`)
   → `se-mobile-play-<версия>.aab`.
2. Play Console → **Тестирование → Закрытое тестирование** (или сразу
   «Рабочая версия», если аккаунт организации) → «Создать выпуск».
3. Подпись: «**Использовать ключ, созданный Google**» (Play App Signing).
   Наш ключ из секрета `KEYSTORE_BASE64` становится ключом загрузки — им CI и
   подписывает `.aab`. **Ключ не терять:** без него новую версию не загрузить
   (восстановление — через поддержку Google, неделями).
4. Загрузить `.aab`, в «Что нового» — пару строк, «Сохранить» → «Отправить на
   проверку». Первая проверка — от нескольких дней до недели; дальше — часы.

## Каждое следующее обновление

Поднять версию (`pubspec.yaml` и `lib/utils/app_version.dart`, номер сборки
после `+` — обязательно больше прежнего), слить в `main`, скачать новый
`.aab` из верхнего релиза в Releases и загрузить его как новый выпуск. Тот же номер сборки
уходит и в `.apk` для сервера — расходиться им незачем.

## Когда подключат Firebase

Уведомления привязаны к имени пакета. В проекте Firebase нужно будет завести
**два** Android-приложения — `com.sebtrz.mobile` (Play) и
`com.example.se_mobile.se_mobile` (сервер) — и положить общий
`android/app/google-services.json` с обоими.

## Что проверить на телефоне перед первой загрузкой

Целевая версия Android выросла с 34 до 36. С 35-й Android рисует приложение
под строкой состояния и полосой жестов (edge-to-edge); Flutter это учитывает,
но стоит глазами пройтись по главному экрану, нижней панели и диалогам на
телефоне с Android 15 или 16.
